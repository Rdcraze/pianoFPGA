# Phase 0 Board I/O Timing Requirements

Task: `task-c8fb8ab4`  
Date: `2026-04-24`  
Scope: local board/manual/datasheet/example collateral only. No RTL feature changes proposed.

## Findings

1. The WM8978 digital audio pins have useful datasheet timing numbers for the current Phase 0 codec-master contract. In master mode, the codec drives `audio_bclk` and `audio_lrc`; the FPGA drives `audio_mclk` and `audio_dacdat`. The key timing numbers are:
   - `audio_mclk`: period must be compatible with WM8978 system clock timing; the datasheet lists `81.38 ns` for `MCLK = SYSCLK = 256fs` and requires a `40:60` to `60:40` duty-cycle window.
   - `audio_lrc`: generated by WM8978, propagation delay from `BCLK` falling edge is max `10 ns`.
   - `audio_adcdat`: generated by WM8978 if ADC capture is used, propagation delay from `BCLK` falling edge is max `10 ns`.
   - `audio_dacdat`: sampled by WM8978 on `BCLK` rising edge and needs `10 ns` setup and `10 ns` hold.
2. The current Phase 0 `12.000 MHz` direct-MCLK / codec-master model is defensible as a bring-up timing model, but it is not exact `48 kHz`: current SDC models `audio_bclk` as `1.500 MHz` (`666.667 ns`) and comments that this represents `32 * 46.875 kHz` framing.
3. WM8978 2-wire control timing is slow enough for the current 250 kHz controller. The datasheet allows SCLK up to `526 kHz`; requires low pulse width `1.3 us`, high pulse width `600 ns`, start hold/setup `600 ns`, data setup `100 ns`, rise/fall max `300 ns`, stop setup `600 ns`, and data hold max `900 ns`. The local WM8978 controllers in Phase 0 and bundled examples use `SCL_FREQ = 250_000`, which gives a nominal `4 us` SCL period with roughly `2 us` high and `2 us` low phases.
4. UART1/CH340 is asynchronous serial debug I/O. It has no source-synchronous clock to constrain with board-level setup/hold. It should be documented as baud-tolerant asynchronous I/O, with `uart1_rx` treated as asynchronous input and `uart1_tx` treated as an unclocked serial output for SDC purposes.
5. No local board document found gives trace length/skew or package-to-codec board delay numbers for WM8978, I2C, or UART. Any PCB delay margin in SDC must therefore be labeled as an assumption, not a sourced board value.

## Interface Requirements

### WM8978 Master Clock: `audio_mclk`

Direction: FPGA to WM8978.

Relevant model:

- Phase 0 generates `audio_mclk` from a PLL at `12.000 MHz`.
- Bundled `42_audio_loopback` and `59_audio_sd_play` also generate `audio_mclk` from the FPGA and label it as `12 MHz`.
- WM8978 datasheet system-clock timing lists `TMCLKY = 81.38 ns` for `MCLK = SYSCLK = 256fs`, and a `40:60` to `60:40` MCLK duty-cycle requirement.

Requirement:

- Keep `audio_mclk` modeled as a generated/output clock from the FPGA PLL.
- Do not invent a data-style `set_output_delay` for `audio_mclk`; this is a clock input to the codec, not data captured by another off-chip clock.
- Current Phase 0 `12.000 MHz` period is `83.333 ns`, which is longer than the datasheet's `81.38 ns` reference period and is inside the intended bring-up contract.

Assumption:

- No board-level trace delay/skew value is documented locally for `audio_mclk`; if the SDC adds output clock uncertainty or board skew, the numeric value must be labeled as an assumption.

### WM8978 Audio Clock/Data: `audio_bclk`, `audio_lrc`, `audio_dacdat`, `audio_adcdat`

Directions:

- `audio_bclk`: WM8978 to FPGA in codec-master mode.
- `audio_lrc`: WM8978 to FPGA in codec-master mode.
- `audio_dacdat`: FPGA to WM8978.
- `audio_adcdat`: WM8978 to FPGA, but unused in current playback-only Phase 0 RTL.

Relevant model:

- The current SDC already creates `audio_bclk` as an external clock at `1.500 MHz`, period `666.667 ns`.
- `rtl/peripherals/wm8978_dac_tx.v` samples `audio_lrc` in the `audio_bclk` domain and drives `audio_dacdat` on `audio_bclk` falling edge.
- WM8978 master-mode timing states:
  - `LRC` propagation delay from `BCLK` falling edge: max `10 ns`.
  - `ADCDAT` propagation delay from `BCLK` falling edge: max `10 ns`.
  - `DACDAT` setup to `BCLK` rising edge: min `10 ns`.
  - `DACDAT` hold from `BCLK` rising edge: min `10 ns`.

Requirements:

- Keep `audio_bclk` as the external timing clock for the codec-driven audio island.
- For `audio_lrc`, model input arrival relative to `audio_bclk` falling edge with max `10 ns`; use min `0 ns` as an explicit assumption because the datasheet provides only the max propagation delay in the extracted table.
- For `audio_adcdat`, if it remains pinned but unused, document it as an unused input. If it is timed for completeness, use the same max `10 ns` from `BCLK` falling edge and min `0 ns` assumption as `audio_lrc`.
- For `audio_dacdat`, model the codec requirement as `10 ns` setup and `10 ns` hold around `audio_bclk` rising edge.

Assumptions:

- No local board material gives trace skew between `BCLK`, `LRC`, `ADCDAT`, and `DACDAT`. The numbers above are device-side timing requirements, not full PCB signoff values.
- The current direct-MCLK contract uses `12.000 MHz` MCLK and nominal `46.875 kHz` sample framing. If Phase 0 later changes to exact `48 kHz` through codec PLL programming, the `audio_bclk` frequency model must be revisited.

### WM8978 2-Wire Control: `i2c_scl`, `i2c_sda`

Directions:

- `i2c_scl`: FPGA to shared I2C bus / WM8978 `SCLK`.
- `i2c_sda`: bidirectional open-drain shared I2C data.

Relevant model:

- The WM8978 is in 2-wire control mode on this board and has fixed 7-bit address `0011010`.
- The schematic labels the WM8978 control address as `0x1A` and ties it to the shared `I2C1_SCL` / `I2C1_SDA` bus.
- The local Phase 0 controller and bundled audio examples use `SCL_FREQ = 250_000`.
- The schematic shows `I2C1_SCL` / `I2C1_SDA` shared with other board devices, with pullups on the shared bus in the schematic collateral.

WM8978 2-wire timing requirements:

- SCLK frequency: max `526 kHz`.
- SCLK low pulse width: min `1.3 us`.
- SCLK high pulse width: min `600 ns`.
- Start hold time: min `600 ns`.
- Start setup time: min `600 ns`.
- Data setup time: min `100 ns`.
- SDIN/SCLK rise time: max `300 ns`.
- SDIN/SCLK fall time: max `300 ns`.
- Stop setup time: min `600 ns`.
- Data hold time: max `900 ns`.

Requirements:

- Treat `250 kHz` SCL as the practical Phase 0 I2C timing assumption.
- For SDC, `i2c_scl`/`i2c_sda` should be modeled or excluded with comments that reflect open-drain 2-wire control timing, not push-pull synchronous data timing.
- If explicit I2C I/O constraints are added, they should be based on the WM8978 numbers above and should keep the bus below `526 kHz`. The current `250 kHz` controller has enough nominal timing margin against the datasheet low/high pulse-width requirements.

Assumptions:

- No local board document gives measured I2C bus capacitance or rise/fall time. The datasheet's `300 ns` rise/fall max is therefore a requirement for board behavior, not locally verified evidence.
- Because `i2c_sda` is bidirectional and open-drain, final SDC may need separate input/output treatment or a documented timing exclusion depending on Quartus support in this project.

### UART1 / CH340: `uart1_rx`, `uart1_tx`

Directions:

- `uart1_tx`: FPGA to CH340 RX path.
- `uart1_rx`: CH340 TX path to FPGA.

Relevant model:

- Board manual and schematic show a Type-C CH340 USB-UART path routed to FPGA `UART1`.
- Board manual requires jumpers crossing `TX -> RXD` and `RX -> TXD` for the USB-UART path.
- The current Phase 0 UART transmitter is `115200` baud, `8N1`, generated from `50 MHz`.
- Bundled `55_uart_sd` confirms the CH340-facing UART pin route with `rx = N6` and `tx = N5`; it uses a slower example baud by default, so do not copy its baud value into Phase 0.

Requirement:

- Do not add ordinary source-synchronous input/output delays for UART1. There is no UART clock at the FPGA/CH340 boundary.
- Document `uart1_rx` as an asynchronous input. If the SDC needs to suppress false setup/hold analysis on this input, use an asynchronous timing exception with a clear comment.
- Document `uart1_tx` as an unclocked asynchronous serial output. Its correctness is governed by baud-rate error and receiver tolerance, not FPGA-to-external-clock setup/hold.

Assumptions:

- No local CH340 datasheet or board document gives a UART timing aperture to constrain at the FPGA pins. Live board reports already validate CH340 observability at `115200 8N1`, but that is functional evidence rather than a board timing number.

## SDC-Oriented Summary For Implementer

Use these values as the local-source-backed starting point for `task-241de457`:

- Keep `sys_clk_50m = 20.000 ns`.
- Keep `audio_mclk` as a PLL-derived `12.000 MHz` generated/output clock; verify duty cycle remains inside `40:60` to `60:40`.
- Keep `audio_bclk = 666.667 ns` while Phase 0 remains on the current direct-`MCLK` codec-master contract.
- Model `audio_lrc` input from WM8978 as max `10 ns` after `audio_bclk` falling edge; min `0 ns` is an assumption.
- Model `audio_adcdat` the same way only if the unused ADC input is included in timing closure; otherwise document it as unused/playback-only.
- Model `audio_dacdat` output to meet WM8978 `10 ns` setup and `10 ns` hold around `audio_bclk` rising edge.
- Model or explicitly justify I2C using WM8978 2-wire timing: max `526 kHz`, low `1.3 us`, high `600 ns`, data setup `100 ns`, data hold max `900 ns`, rise/fall max `300 ns`.
- Treat UART1/CH340 as asynchronous serial debug I/O, not as a board-level setup/hold interface.

Residual caveat: this report provides device timing and local board route evidence. It does not provide measured PCB trace delays, skew, or signal-integrity margins because those values are not present in the local manuals, schematic, datasheets, or bundled examples I inspected.
