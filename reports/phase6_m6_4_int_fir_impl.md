### 2.2 Source-to-effective-delay mapping (verifier-corrected)

The M6.4-INT scope (commit `c333e3d`) initially proposed
constants `5'd5/13/25` under the assumption that the
read-pipe latency added one cycle, mapping source-N to
effective-(N-1). Verifier task-8844ef33 proved this was
wrong: the source constant IS the effective delay because
the read-pipe register was already accounted for in the
M6.3a-era 7/17/31 baseline. So `5'd5/13/25` actually
implements **Cand A** (effective delays 5/13/25), not
Cand E.

The task description is explicit: "source constants 5'd5/13/25
implement Cand A, not Cand E." This implementation uses the
corrected `5'd4/12/24` constants for true Cand E (effective
delays 4/12/24).

### 2.3 What is preserved

- Body FIR weights and signs: `+ body_tap6 >>> 2 -
  body_tap16 >>> 3 + body_read_data >>> 4`.
- M6.3a body-doubling shift: `sat_q18(... <<< 1)` in
  `STATE_BODY_TAP30`.
- M6.2 MSB-saturating body_mix mapping:
  `body_mix_q15[15] ? 16'sd32767 : $signed({1'b0,
  body_mix_q15[14:0]})`.
- All other states, the read-pipe latency structure, the
  body_history depth-32 layout, and the saturation behavior
  in `STATE_BODY_FINISH`.

### 2.4 Worst-case headroom

Cand E weights are unchanged. Pre-shift `mult_sample`
magnitude bound is identical to M6.3a:
`body_partial_max = 7/16 * peak_q18 * 2 (post-doubling) =
7/8 * 131071 = 114688`, still inside Q18 +/-131071. The
doubling shift's `sat_q18` already caps. Existing
`STATE_BODY_FINISH` clip detection is unchanged.

The only thing the delay change affects is **when** the body
content drives the multiplier - which strikes a different
spectral fingerprint - not the magnitude bounds.

`body_history` depth is 32 entries; max delay 24 < 32, so
no memory layout change.

## 5. Why Cand E (effective delays 4/12/24)

From the M6.4-INT scope analysis at commit `c333e3d`
(verifier-validated at `task-8844ef33`):

Cand E predicted band-averaged body_mix delta from
`0x1000 -> 0x7000`:

```
band      M6.3a (7/17/31)    Cand E (4/12/24)  M6.3a hardware (energy-mean)
50-200    +2.02              +2.04             +0.01
200-500   +1.80              +1.88             +1.25
500-1k    +1.76              +1.65             +1.56
1-2k      +2.49              +2.78             +0.00
2-3k      -2.56              +2.55             +0.61
3-5k      -1.25              -2.09             -0.32
```

Key differences:

1. **2-3 kHz: -2.56 dB -> +2.55 dB**. The 5 dB swing in
   2-3 kHz from cancellation to additive interference is
   the main payoff. Shorter delays move the FIR's first
   phase-cancellation zero out of the acceptance band.
2. **1-2 kHz: +2.49 -> +2.78 dB**. Modest improvement.
3. Other bands are essentially unchanged.

Phase at 2.5 kHz moves from -148 deg (cancelling against
disp) to -73 deg (constructive). Predicted: Cand E should
clear the +1 dB CONDITIONAL_PASS gate in both 1-2 kHz and
2-3 kHz, and probably clear PASS (>= +3 dB) in 1-2 kHz.

Hardware verification is the verifier's job per project
discipline.
