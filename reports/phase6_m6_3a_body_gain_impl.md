### 2.2 What the shift does

End-to-end body contribution at the audio sum
`disp_sample + body_contrib` (where `body_contrib =
mult_sample * mult_coeff / 32768`):

- M6.2: `body_contrib_max ~= +/-14336 (typical) * +32767 /
  32768 ~= +/-14336` Q18 units.
- M6.3a: `body_contrib_max ~= +/-28672 (typical) * +32767 /
  32768 ~= +/-28672` Q18 units. **Doubled.**

Worst-case bound:

- Pre-shift `mult_sample` magnitude is 7/16 of peak Q18 tap
  (`+/-131071 * 7/16 = +/-57344`), but practical taps are
  bounded by the audio amplitude and `sat_q18` further
  bounds to `+/-131071`.
- Post-shift `mult_sample <<< 1` magnitude is 7/8 of peak Q18
  tap (`+/-114688`), still inside `sat_q18`'s `+/-131071`
  bound. The saturation catches the rare worst case.

Saturation safety at `STATE_BODY_FINISH` (the disp+body sum):

```
output_sample_q18 = sat_q18(disp_sample + product_to_q18(mult_product))
```

The existing `clip_seen` register already detects when this
sum exceeds Q18 bounds; `sat_q18` clamps it. With body
doubling, the worst-case sum becomes
`+/-32768 + +/-28672 = +/-61440`, still inside Q18 bounds.
No new clipping mechanism is required.

### 4.2 ModelSim `vsim` blocked by license

Per `implementer_handoff.md` "Quartus And Hardware Commands"
section, `vsim` cannot complete on this host:

```
** Fatal: Invalid license environment. Application closing.
Unable to checkout a license. Make sure your license file
environment variable (e.g., LM_LICENSE_FILE) is set
correctly and then run 'lmutil lmdiag' to diagnose the
problem.
```

Consequence: the existing
`rtl/audio/phase1_reduced_voice_golden_samples.hex` cannot
be regenerated by implementer. With M6.3a's `mult_sample`
doubling, the captured 4096-sample golden will differ from
the M6.2-era golden (predictably, mostly by larger
post-strike body-contribution amplitudes). Running
`phase1_reduced_voice_tb` against the stale golden will
fail at the first sample mismatch.

**The implementer commit therefore intentionally leaves the
golden hex file untouched, rather than fabricating a new
one without empirical evidence.** The verifier task text
from the M6.3 scope and the M6.3a task description both
explicitly contemplate this: with a valid ModelSim license,
verifier regenerates via `+WRITE_GOLDEN` and reruns the
TBs.

### 4.4 Static equivalence at body_mix_q15 = 0x3000

For the in-range default value `body_mix_q15 = 0x3000` (the
golden TB body_mix value), the `mult_coeff` mapping is:
- M6.2 / M6.3a: both produce `+12288` (high bit clear, low
  15 bits pass through).

But `mult_sample` itself doubles in M6.3a, so the product
doubles and `output_sample_q18` differs from M6.2.
**Therefore the existing `phase1_reduced_voice_tb` golden
will mismatch under M6.3a until regenerated.** This is
expected and is the verifier's regeneration responsibility
documented in 4.2.

The body_mix_sat_tb's bit-equality assertion across
`0x7FFF`/`0xC000`/`0xFFFF` is preserved because the body
shift applies uniformly.
